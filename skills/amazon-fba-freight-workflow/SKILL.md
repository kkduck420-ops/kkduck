# FBA发货与货代交接

把本批装箱事实转成可核对的货件、发票、箱标和追踪记录。以用户本次指定的店铺、货代、停止位置及已有授权为准；读取技能本身不授权创建或提交货件。

## 工作方式

- 优先使用本机已登录紫鸟的 `ziniao-cli`。已有 `ziniao-store`、`ziniao-page` 技能时按其入口操作；缺少时通过CLI帮助发现当前可用命令，不照抄旧版参数。CLI不能完成的原生文件窗口等操作，再使用可用的Computer Use。
- 新设备本地完成CLI认证和店铺授权，先运行 `ziniao-cli doctor`。只读取得当前店铺及页面标识，核对商家和站点；不沿用另一台电脑的窗口标识、文件绝对路径或登录配置。
- 每票复用实际工作流程和装箱记录，避免把旧批次建议、已发批次或已存在的货件重新创建。仅检查时保持线上只读。
- 团队默认场景是红珊瑚美国站，偏好自己的承运人、单仓合仓、不选AWD；用户本次指定的店铺和方案可覆盖这些偏好。SPD或LTL按本票真实安排确定，不能用默认下拉值或海运渠道名称推定尾程方式。

## 按任务读取

- 新电脑安装、CLI缺失或分享给同事：读 [设备安装与共享](references/setup-and-sharing.md)。
- 建货件、选仓、箱标或追踪：读 [货件工作流程](references/shipment-workflow.md)。
- 填货代发票：读 [发票模板字段与验收](references/invoice-template.md)，复制 [固定模板](assets/fba-invoice-template.xlsx) 或用户本次提供的新版本。模板更新以用户指定版本优先。

## 关键交接

1. 核对SKU/ASIN、中文简称、逐箱数量、外箱尺寸和毛重。用户明确更正覆盖旧表值；不根据相近商品名称合并不同款式。
2. 到仓库预览时，汇总仓库地址、拆分数量、配置费和货代运费缺项，并附可直接转发货代的话术。用户要求“到仓库位置暂停”就停在确认费用之前；已授权继续且方案在已确认范围内则直接完成，不反复索要同一批准。
3. 确认后分别记录正式FBA货件号、PO/Amazon Reference ID、每箱箱标ID。下载标签并核对页序与实物箱的对应；打印偏好是100×100mm、一箱一页，不能只改文件名就称已转换。
4. 填发票时沿用有依据的本款历史资料。货代负责的未知申报字段留空；不把整箱毛重写成单件重量，不把模板默认“不带电”当本批确认。
5. 对已验证支持箱号关联的同一货代渠道，可逐箱将各自箱标ID填入追踪栏，保存后刷新核验；不一概要求先等另一个物流号。检查是否已关联真实第三方物流编号和轨迹。其他渠道按实际要求填写，不固定号码前缀或所有箱都共用一号。

## 完成与记录

分别核对后台持久化、正确货件及箱数、标签/发票文件、逐箱追踪状态。界面可能短暂残留旧值；刷新后再判定，保存响应不清楚时先检查结果再重试。

简要汇报：货件/PO、仓库、箱数和件数、费用、箱标对应、发票路径、追踪确认数，以及当前真实运输节点。区分“后台流程完成”“配送商收货”“已开船”“亚马逊接收”。本地留核验时间、来源与未解决项；不要把实际票据、个人联系方式或登录配置提交到共享技能仓库。
