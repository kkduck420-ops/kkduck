# 发票模板字段与验收

先复制用户指定模板或 [随附固定模板](../assets/fba-invoice-template.xlsx)，每票生成新的输出，不覆盖空白原版或历史发票。若本机有Spreadsheets技能，按其导入、编辑、渲染和导出流程操作。

## 模板结构

这个模板含 `发票`、`填写示例`、`！` 三张表；`！` 保存下拉和仓库地址查找数据。不要改表名或无关数据区。格式相似不代表坐标一定相同；用户给新版时，先检查标签、合并范围和公式再用此映射。

### 主信息（发票表）

| 单元格 | 内容 | 填写依据 |
|---|---|---|
| B3 | 客户参考号 | 本批实物箱号或用户给的业务参考 |
| B4 | 运单号 | 货代实际运单；未知留货代填写 |
| B5 | FBAID | 亚马逊正式FBA货件号，不填工作流程号 |
| B6 | POAnumber | 货件摘要的Amazon Reference ID/亚马逊内部编号，核对货代要求 |
| B7 | 收货渠道 | 货代确认的准确下拉名称；不要擅自映射相似别名 |
| B8 | 目的地 | 当前货件实际国家/站点 |
| B9 | 预报件数 | 本批外箱数量，不是商品件数 |
| B10 | 报关类型 | 用户或货代确认；未知留空 |
| B11 | 是否带电 | 本批真实装有/附送电池情况；未知留空 |
| B12 | 交仓地 | 本批实际交仓站，不把模板默认站点当确认 |
| E3 | 仓库代码 | 当前已选目的仓 |
| E4:E10 | 收件地址、电话、公司 | 通常由仓库代码VLOOKUP查找，逐项与当前亚马逊地址比对 |
| E11 | 运单备注 | 已确认渠道原名、计划船期、总毛重等有用信息；不填内部工作备注 |

B6旧模板曾有“8位追踪码”的说明文本。它不是实际号码，也不意味着将该PO填到逐箱物流追踪栏。使用当前货件摘要与货代要求确认，不复制旧票值或提示文本。

原模板曾默认“不带电”、某个交仓站和某个仓库代码；这些不是新票事实。带LED不能单凭名称判断是否随货带电池。用户已要求其他未知申报字段交货代补填时，保留这些字段空白，不反复追问相同信息。

### 装箱明细（第15行开始）

| 列 | 内容 | 关键区别 |
|---|---|---|
| A | 实物箱号 | 保持用户的外箱编号 |
| B/C | 中/英文品名 | 本款真实用途，不混用相近型号 |
| D | 单箱内数量 | 销售包装件数 |
| E | 申报单价USD | 仅依据本款确认资料或适用历史申报，不抄零售价或物流单价 |
| F/G | 中文材质/用途 | 有实物或适用资料依据 |
| H/I | 品牌/型号 | 正确款式和颜色SKU |
| J | 海关编码 | 已确认资料；未知留货代填写 |
| K | 单件实重 | 不能填整箱毛重；未知留空 |
| L/M/N | 外箱长宽高 | 检查模板要求单位，保留本批正确三维 |
| O | 产品图片 | 对应本箱SKU的真实图片，使用浮动图 |
| P | 销售链接 | 正确子ASIN或产品链接 |

一箱多SKU时按货代模板要求展开，不能套用本例“一箱一个SKU”的行关系。保持可核对的箱号和件数汇总。

## 填写与文件验收

- 清除模板旧样例商品和旧图，保留格式、合并、打印设置、下拉和无关辅助表。申报单价与材质可沿用确认适用于本款的历史资料，不能把一条旧SKU的资料无依据套到另一款。
- 图片必须与本箱款式对应；使用用户实拍或该正确子体的实际商品图，不生成替代实物图片。固定模板要求浮动图，不把图片变成单元格文字或无效路径。
- 仓库查找结果与亚马逊实际地址一致才通过。未知电话显示0时，应保留为空白，而不是交付一个“0”电话号码；保留其他有效地址公式。
- 以真实数字和正确单位填件数、价格及尺寸。独立核对外箱总数、商品总数以及数量×申报单价的金额；不要把人民币运费与美元申报价值混合。
- 导出后重新读取关键值和公式并查看最终可见范围。若导入/导出改变了无关地址库、样例表、合并或验证，先恢复这些范围再交付，不能只凭预览正常认定完整。
- 最终只交付本批正式文件，说明留给货代的字段与实际保存位置；不把日志、预览或本机绝对路径写入发票内容。
